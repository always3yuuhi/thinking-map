# 位置情報日記自動生成アプリ 仕様書

## 1. 概要

### 1.1 目的
ユーザーの1日の移動記録(訪問地点・滞在時間・移動手段)を自動的に記録し、その記録をもとにAIが自然な文章の「日記」を自動生成するアプリ。

### 1.2 背景・重要な前提(制約事項)
当初の想定は「Googleマップのタイムラインを自動取得する」というものだったが、以下の技術的制約により、この方式は現実的に実現できない。

- Googleはタイムライン(位置情報履歴)データを2024年頃からGoogleのサーバーではなく**端末本体にのみ保存**する仕様に変更した
- そのため Google Takeout(データエクスポート)経由では**空のデータ**しか取得できない
- タイムラインデータを外部アプリが自動的に読み取るための公式API(Timeline API)は現在提供されていない
- 唯一の取得手段は、ユーザーが手動でGoogleマップアプリから「タイムラインデータをエクスポート」を都度実行し、JSONファイルを出力することのみ

**→ 結論:「Googleタイムラインを裏で自動取得する」設計は不可。**
本仕様書では、代わりに**アプリ自身が位置情報を記録する自前のロギング方式**を採用する。これにより「自動化」の目的(=ユーザーが何もしなくても日記ができる)を達成できる。

### 1.3 想定ユーザー
- 日々の記録・振り返りを習慣化したい個人ユーザー(まずはKoichi自身が主なユーザー)

---

## 2. 全体アーキテクチャ

```
[スマホ端末]
  ├─ バックグラウンド位置情報サービス(常時 or 一定間隔でGPS取得)
  ├─ ローカルDB(SQLite等)に位置ログを蓄積
  ├─ ジオコーディング/場所名解決(訪問地点の名称特定)
  ├─ 滞在・移動の区間分割ロジック(スポット検出)
  ├─ 1日の終わり(例: 23:00等)に自動集計
  ├─ Claude API 等のLLMに集計データを渡し、日記文を生成
  └─ 日記を表示・保存・(任意で)Notion等へ自動投稿
```

---

## 3. 機能要件

### 3.1 位置情報の自動収集
- バックグラウンドで一定間隔(例: 3〜5分ごと、または移動検知時のみ)で位置情報を取得
- バッテリー消費を抑えるため、静止時は取得頻度を下げる(Geofencing / Activity Recognition APIの活用)
- 取得データ: 緯度経度、取得時刻、移動手段の推定(徒歩/車/電車等、Android Activity Recognition APIやiOS Core Motionを利用)

### 3.2 訪問地点の自動検出・命名
- 一定時間(例: 5分以上)同一エリアに滞在した場合を「訪問地点」として区間検出
- 逆ジオコーディングAPI(Google Geocoding API等)で住所・施設名を取得
- ユーザーが場所にエイリアス(表示名)を設定できる機能(例:「自宅」「会社」など個人的な呼び名への変換)

### 3.3 移動区間の検出
- 訪問地点間の移動を「移動区間」として記録
- 移動手段・移動時間・距離を算出

### 3.4 日記の自動生成
- 1日の終わりに、その日の訪問地点リスト・滞在時間・移動手段データをLLM(Claude API)に渡す
- 「午前中は〇〇で過ごしました、その後△△へ移動し…」のような自然な日本語の文章を自動生成
- 生成した日記はアプリ内に保存し、日付ごとに一覧・検索できる

### 3.5 手動編集・補足
- 自動生成された日記に、ユーザーが手動でコメントや感想を追記できる
- 場所の誤認識(ジオコーディングの間違い)を手動修正できる

### 3.6 データのエクスポート・連携(任意)
- 日記をNotion、Google Docs、テキストファイル等へエクスポート
- 過去のGoogleタイムラインJSON(手動エクスポート分)を一括インポートして遡って日記化する機能

---

## 4. 非機能要件

| 項目 | 内容 |
|---|---|
| バッテリー消費 | 常時GPS取得は避け、Activity Recognitionと連動した間欠取得を基本とする |
| プライバシー | 位置情報はローカルDBを基本とし、LLMへの送信は集計後のテキストデータのみに限定 |
| オフライン対応 | 位置ログの記録自体はオフラインで可能、日記生成のみネットワーク接続が必要 |
| 対応OS | Android(Kotlin)を優先、将来的にFlutterでのクロスプラットフォーム化も検討 |

---

## 5. 想定技術スタック

- **アプリ本体**: Flutter または Kotlin(Android) — Koichiさんの既存スキルセットに合わせて選択
- **位置情報取得**: `geolocator` (Flutter) / FusedLocationProviderClient (Android)
- **行動認識**: Activity Recognition API(移動手段推定)
- **逆ジオコーディング**: Google Geocoding API または OpenStreetMap Nominatim
- **ローカルDB**: SQLite(sqflite / Room)
- **日記生成**: Claude API(Anthropic)
- **バックグラウンド処理**: WorkManager(Android)/ flutter_background_service

---

## 6. 画面構成(案)

1. **ホーム画面**: 今日の移動ログのタイムライン表示 + 今日の日記(生成前は「生成する」ボタン)
2. **日記一覧画面**: 日付ごとの日記をカレンダー/リスト表示
3. **日記詳細画面**: 本文編集、地図上での訪問地点表示
4. **場所エイリアス設定画面**: よく訪れる場所に名前を付ける
5. **設定画面**: 位置情報取得頻度、日記生成トリガー時刻、エクスポート連携設定

---

## 7. 今後の検討事項

- 過去データの移行: すでにGoogleタイムラインに蓄積されている過去データをどう扱うか(手動エクスポート→一括インポート機能で対応可能)
- 日記の文体・トーンのカスタマイズ(丁寧体/カジュアル体、一人称の変更など)
- 写真との連携(訪問地点の写真を自動添付)
- 週次・月次のサマリー機能
